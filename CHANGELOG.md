# Changelog

Release notes. New entries are generated by semantic-release.

## Unreleased

### Features

* action log of every reconciliation, with one-click Undo and batch Undo (History page, Ctrl/Cmd+Z)
* bank rules can be Suggest Only: matching transactions are flagged and a user applies the rule with one click; optional hourly evaluation
* statement closing balance is saved per bank account and date
* banking reports (Bank Reconciliation Statement, Bank Clearance Summary, Cheques and Deposits Incorrectly cleared) inside Bank Reco
* internal transfers: mirror transaction detection across bank accounts and one-step transfer + reconcile
* statement importer understands CR/DR amount markers
* search box on the transaction list; rule-suggested rows pre-fill Bank Coding

### Fixes

* security: the matching queries no longer build SQL from the reference dates, and every Bank Reco endpoint checks access to the bank account, bank transaction, company and vouchers involved
* allocations are capped at the transaction's unallocated amount and at the voucher's bank leg; auto reconcile allocates at most what is left
* an Amount match requires the same direction and currency
* bulk reconcile: failed invoices are reported with the first reason, a failed job cancels only the Payment Entries it created, and each invoice runs under its own savepoint
* statement import: comma-decimal, bracketed and trailing-minus amounts, ambiguous date formats are flagged instead of guessed, bad rows are reported, duplicates are checked on every row, zero rows are skipped
* the "positive amount is Deposit/Withdrawal" choice for a single amount column is saved with the bank's column layout (new custom field `Bank.bank_statement_positive_field`, run `bench migrate`)
* statement closing balance accepts the amount formats of the importer and refuses text
* internal transfers: same-currency check and the day's exchange rate instead of 1
* hourly auto reconcile is queued per bank account on the long queue
* bank rules: the first matching rule wins across both modes, and a rule does not post a second voucher when an existing one already matches
